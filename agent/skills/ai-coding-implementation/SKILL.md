# AI Coding 实施流程

这个 skill 用于已经进入开发实施的任务。目标是使改动聚焦、可验证、可回顾，而不是扩大重构范围。

## 1. 锁定改动边界

1. 根据用户需求列出可验证的完成条件。
2. 先用 `grep` 或 `glob` 定位入口、调用方和现有测试，再读取具体文件。
3. 只修改与完成条件直接相关的代码；发现无关问题时记录为风险，不顺手重构。

## 2. 实施与兼容性检查

1. 优先沿用现有抽象、命名和依赖，避免创建重复封装。
2. 路径使用 `pathlib` 或项目已有路径层，不手写 `/` 或 `\\` 拼接宿主机路径。
3. 执行系统命令时同时考虑 macOS 和 Windows 的可执行文件名、虚拟环境目录与输出编码。
4. 只在复杂分支、安全边界或兼容性原因不容易从代码中看出时添加简短中文注释。

## 3. 分层验证

1. 先运行与改动文件直接相关的最小测试或语法检查。
2. 最小验证通过后，再运行项目已定义的完整测试或静态检查。
3. 测试失败时先判断是本次回归、环境缺失还是原有故障，不用猜测代替证据。

## 4. Git 收尾

1. 通过 `git status` 和 `git diff` 复核改动范围，确认没有密钥、临时文件或用户的无关改动。
2. 仅当用户要求提交或推送时，才执行 `git add`、`git commit`、`git push` 和 Pull Request 操作。
3. 最终说明修改内容、已运行的验证、未验证范围和剩余风险。
